# 看门狗

`bridge-watchdog.sh`：检查三个桥接的 serve 进程，挂了就重启。

## 检查逻辑

1. **查进程**：按工作目录匹配 `bridge.py serve` 的 python 进程。微信/飞书/企微各只允许一个，找到就过。
2. **查日志活性**：进程存在也不代表连接活着（飞书/企微的 WebSocket 会静默断开）。看 `serve.log` 的修改时间：
   - 微信/企微：300 秒无新日志 → 视为假死，kill -9 后重启
   - 飞书：600 秒无新日志 → 视为假死，kill -9 后重启（飞书无定期心跳日志，阈值放宽）

微信是 HTTP 长轮询（45 秒必有一次请求日志），企微有 30 秒 JSON 心跳日志，飞书只有事件日志，所以阈值不同。

## cron 配置

每 5 分钟跑一次：

```bash
# 用 cron 工具添加 interval 任务，每 5 分钟执行：
bash ~/workspace/bin/bridge-watchdog.sh
```

无输出即正常，有重启动作会打印时间戳和 pid。

## 注意

- VM 重启后所有进程都死，看门狗 cron 本身也依赖 runtime，重启后需**手动**跑一次看门狗或三个 serve。
- 重启 serve 前务必确认旧进程已杀干净，尤其是飞书（单播连接，多余进程会吞事件）。
